# cms-system

A personal content management system: blogs, posts, projects and files, edited in the browser and served to a public site.

## What it does

You authenticate with Auth0, then create blogs (`Blogs.vue`), write posts in a TipTap rich-text editor (`frontend/src/views/Write.vue`), attach images and audio, tag posts, and manage "projects" with status/category fields. Posts can be summarised on demand via Groq (`SummarizeCommandHandler`). `PublicEndpoints.cs` exposes the unauthenticated read side — published blogs and posts by slug — plus file downloads from R2.

## How it works

Entry point is `backend/Host/Program.cs` (33 lines): it registers OpenAPI with a bearer-security transformer, then calls `AddApi()` / `AddApplication()` / `AddInfrastructure()`, maps each layer's endpoints, and runs. The backend is Clean Architecture across seven projects:

- `Domain` (315 lines) — `Post`, `Blog`, `Project`, `FileItem`, `BlogKind`, `ProjectCategory`.
- `Application` (1,684 lines) — command/query handlers per feature (`Blogs/`, `Posts/`, `Files/`, `Projects/`, `Summarize/`), with `PipelineBehaviours/ValidationBehaviour.cs` running FluentValidation.
- `Infrastructure` (3,650 lines) — EF Core Sqlite, `Services/R2StorageService.cs` (116 lines, AWSSDK.S3) for uploads and a 15-minute backup sync (`R2_SYNC_INTERVAL`), and `GroqService` for summaries.
- `Api` (777 lines) — endpoint groups per feature, `Permissions.cs`, and `Authentication/HasScopeHandler.cs`, which checks Auth0 `scope` claims against policies registered in `DependancyInjection.cs`.
- `Host` — `GlobalExceptionMiddleware.cs` (89 lines) converts exceptions to responses.

Auth is Auth0 JWT bearer: `AddApi` throws at startup if `Auth0:Domain` or `Auth0:Audience` is missing, and every permission policy requires an authenticated user plus a matching scope claim. JSON enums are serialised by name (`JsonStringEnumConverter`) with a comment explaining that ordinal enums silently re-point when reordered.

The frontend is Vue 3 + Nuxt UI 4 + Pinia + TipTap on Vite, typed against `src/services/backend/schema.ts` (1,387 lines, generated by `openapi-typescript` from the backend's OpenAPI document). `auth-fetch.ts` injects the Auth0 access token into API calls.

### Stack

- **C# / .NET 10 + EF Core 9 (Sqlite)** — API, domain and persistence.
- **Auth0 (`@auth0/auth0-vue`, `Auth0.AspNetCore.Authentication`)** — login and scope-based authorisation.
- **Vue 3 + Nuxt UI 4 + Pinia + TipTap** — editing UI; `groq-sdk` for summaries; `openapi-fetch` for the typed client.
- **Cloudflare R2 (AWSSDK.S3)** — file storage and backups.
- **xUnit** — 1,887 lines of backend tests; **GitHub Actions** with path-filtered jobs.

## What works well

- Scope-based authorisation is enforced server-side per permission (`ReadBlogs`, `WritePosts`, `SummarizeArticles`, …) rather than hidden in the UI.
- Backend tests are meaningful: `FileHandlerTests` (342 lines), `DatabaseBackupTests` (230), project boundary/draft-visibility suites, and `CorsOriginPolicyTests`.
- The generated `schema.ts` keeps the frontend typed against the real API surface instead of hand-written DTOs.
- The enum-serialisation comment in `Api/DependancyInjection.cs` documents a non-obvious failure mode.

## What I'd change

- **Zero frontend tests.** `find frontend -name "*.test.ts"` returns nothing — no coverage for `Write.vue` (781 lines), `BlogForm.vue` (266), or any Pinia store.
- `frontend/src/views/Write.vue` at 781 lines is the largest file in the repo and mixes editor setup, uploads, autosave and routing.
- `backend/Infrastructure/Infrastructure/Migrations/` is nested two `Infrastructure` folders deep — a path that looks like a copy-paste mistake and slows anyone reading migrations.
- `DependancyInjection.cs` is misspelled in both `Api/` and `Application/`.
- There is no root `README.md` — the repo has no documented setup, run or deploy steps.

## Still outstanding

- `backend/Seeder/Program.cs:162` has the only TODOs in the codebase, and they are article-template placeholders (`<!-- TODO: describe what this is … -->`) it emits for seeded content — real content is still unwritten.
- `docs/superpowers/specs/` contains designs for file-reference tracking (2026-05-12) and audio upload (2026-08-01); audio is implemented (`AudioExtension.ts`), but nothing marks the file-reference work done or abandoned.
- No e2e tests: `playwright-core` is a devDependency but there is no `tests/` directory or spec files.

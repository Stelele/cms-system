# erpnext-market-survey

A research repository: 1,742 Frappe Forum topics, 830 bootstrapper podcast transcripts and 8 non-English market reports, read by 46 analytical personas to find paid opportunities in the ERPNext ecosystem.

## What it does

The deliverables are documents, not software. `synthesis/master-synthesis.md` (733 lines) ranks ten opportunities — demo/seed-data generator, invoice OCR, emergency update triage, Tally migration, country compliance packs — each with a confidence score and a solo-founder build estimate. Around it sit `research-personas/` (49 persona definitions extracted from MicroConf, Rob Walling and The Bootstrapped Founder transcripts), `persona-outputs/` (39 persona canvases plus two JSON dumps), `market-research/` (India, Brazil, Germany, MENA, Africa, SEA, LatAm, China) and `methodology/` (7 files, including a replication guide with subagent prompt templates).

Two Python scripts do the numeric half. `analyze_topics.py` (244 lines) walks every JSON file in `erpnext-forum/topics/`, strips HTML from the Discourse `cooked` field, drops blockquotes, computes views/replies/likes totals, matches 25 keyword buckets ("pain patterns" such as `willing to pay`, `frustrated`, `is there an app`) and writes `structured_topics.json` (4 MB) and `is_there_apps.json`. `deep_analysis.py` (311 lines) reads that JSON back and buckets topics into 14 module areas, then deep-dives reporting, migration, banking and AI.

## How it works

There is no entry point in the usual sense: both scripts are top-level, run as `python analyze_topics.py`, and print everything to stdout. `analyze_topics.py` loads from `TOPICS_DIR` (line 6), builds `_full_text` per topic by concatenating every post's stripped text, then does a linear scan per keyword bucket — `pain_counts[pattern_name].append(t['topic_id'])` with a `break` after the first keyword hit, so each topic counts once per bucket. `deep_analysis.py` repeats the same keyword-scan shape against `module_keywords`.

No external services are called. The corpus is committed: 1,742 topic files under `erpnext-forum/topics/`, 830 `.txt` transcripts under `bootstrappers/`, `topic_index.csv` (89 KB).

### Stack

- **Python 3, stdlib only** — `json`, `os`, `re`, `collections.defaultdict`. No third-party imports anywhere.
- **No manifest** — no `requirements.txt`, `pyproject.toml` or `setup.py`, because nothing is installed.
- **Markdown + JSON + CSV** — the actual product; persona and synthesis prose is hand-written, not generated by these scripts.

## What works well

- The corpus is fully committed and reproducible in place: you can read any cited topic ID (`150923` is the $5,000 seed-data offer) straight from `erpnext-forum/topics/150923.json`.
- `methodology/replication-guide.md` (15,860 bytes) documents the subagent prompts, token budgets and failure modes, so the *process* is replicable even though the code is not.
- The README is honest about limits — English-only forum bias, Telegram communities missing, no primary-research validation — rather than overselling the ranking.

## What I'd change

- **Both scripts are hard-wired to one laptop.** `analyze_topics.py:6-7` and `deep_analysis.py:6` open `C:\Users\Gifts Laptop\Documents\code-projects\sidehustles\opportunity-analysis\...`. Clone this repo anywhere else, including this machine, and both fail immediately. Path arguments or `pathlib.Path(__file__).parent` would fix it in one line each.
- **Substring keyword matching produces false positives.** `analyze_topics.py:127` tests `if kw.lower() in text` with no word boundaries, so the `'ai/openai'` bucket's bare `'ai'` matches inside *email*, *domain* and *paid*, and `'api'` matches *capital*. The pain-pattern counts feeding the ranking are inflated in ways nobody can see from the output.
- `strip_quotes` (line 24) drops any line containing the word `quote` outside a blockquote, silently deleting legitimate posts.
- **No tests**, no TODO markers, no lint config, and the README never mentions the two `.py` files — `grep` for `analyze_topics` or `.py` in `README.md` and `methodology/replication-guide.md` returns nothing.
- The README claims **1,304 bootstrapper transcript files** (repeated three times: lines 4, 135, 191); the repo contains **830** `.txt` transcripts.

## Still outstanding

- Parameterising the two scripts so they run outside the original Windows path.
- `is_there_apps.json` is written by `analyze_topics.py:201` but is not committed, while `structured_topics.json` is — an inconsistent output set.
- The README's own listed gap: no primary research validating willingness-to-pay, and no Telegram corpus for the non-English markets the synthesis leans on.
- Only one git commit (`added readme`, 2026-04-01), so there is no history tying scripts to the numbers in the synthesis.
